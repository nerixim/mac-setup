# 開発者向けEN↔JA用語集

Issue・PR・コミット・ops文面・コードコメント向け。プロダクトのUI文言はそのリポジトリのガイドラインを正とする。

原則: **日本語の文に英語語幹を裸で挿さない**（ルー大柴化）。識別子・型名・コマンド・テーブル名はバッククォートで隔離する。カタカナ定着語は文脈ごとに使い分ける。

## AI臭い常套句（避ける）

LLMが好む言い回し。単体では誤りでないが、積むと「生成された文」に読める。出典は [coji/natural-japanese](https://github.com/coji/natural-japanese) の `forbidden-patterns.md`（人間103文書とAI 81文書で校正済み）、[yugen_matuni の Hooks 記事](https://x.com/yugen_matuni/status/2088251220452679951)、[megmogmog1965 の文章スタイルルール](https://qiita.com/megmogmog1965/items/4b668265025cf97ea843)。備考に `W17`〜`W20` とある行は正規表現で `lint-draft` が拾うので、この表からは読み込まない。

| ❌ 避ける | ⭕️ 使う | 備考 |
| :--- | :--- | :--- |
| 効く（中身なし） | 何がどう変わるかを同じ文に書く（「applyが3分→1分になる」） | 検出数1位の癖。効果を書けないなら、まだ測っていない |
| AではなくB（不要な対比） | Bを肯定形で書く | 読み手が本当にAだと誤解しているときだけ対比を使う。W18 |
| 〜と言えます / 〜と言えるでしょう / 〜と言えるだろう / ということになるでしょう | 言い切る | まとめ口調。判断の主体を消す |
| 〜のではないでしょうか | 言い切るか、条件を書く | 意見のない文に見える |
| 結論から言うと / まとめると / 総じて | （削る。最初の一文が結論） | 予告は結論ではない |
| 重要なのは / 大切なのは / ポイントは / 非常に重要 / 極めて重要 | （削る。重要な一文を短く言い切る） | 強調語が均等に散ると、どこも強調に見えない |
| 言うまでもなく / 言うまでもありません / まさしく | （削る） | 「まさに」「最後に」は人間の日常語なので禁止しない |
| さて、 / それでは、 / このように / このような中 / ここで注目したいのは | 前の段落の内容でつなぐ | 空疎な接続 |
| 見ていきましょう / 紹介していきます / 解説していきます / 深掘りしていきます / について見ていく | （削る。内容から書く） | 予告口調 |
| 掘り下げる / 深掘りする / 言語化する / を探求する / 正面から扱う | 何をどう調べたかを書く | 姿勢の宣言で中身が増えない |
| 不可欠 / 核心的 / 鍵となる / 根本的な / 多角的 / 包括的 / 総合的 | 具体の根拠・視点を書く | 空虚な形容 |
| 一概には言えません / 個人差がありますが / あくまで一例ですが / という側面もあります | 条件を具体的に書く | 予防線 |
| 理由は3つあります / 大きく分けて / ポイントは以下の通りです | （数を宣言せず内容から書く） | 論点の数だけ書く |
| いよいよ / 本題に入ります | （削る） | 装飾的な前置き |
| 見てみます / こうなっています / 開いてみます | 結果を直接書く（「〜が表示されます」） | 実況中継調 |
| 本章の主題です / 最も重要な主題 | 「〜を説明します」か削る | 文章が自分を語る文 |
| 意外と知られていませんが / 驚くべきことに / 興味深いことに | （削る） | 読者の反応の決めつけ |
| 言い直し（つまり〜） | 前の文だけ残す | 「つまり」で始まる文は前文の繰り返しか確認 |
| 近年、 | （削る。具体の事実から入る） | 一般論の水増し |
| と言っても過言ではありません / に他なりません / これこそが | 事実を淡々と書く | 決め文 |
| 以上、〜について解説しました | 要点を1〜2文に再統合 | 結びの反復 |
| 〜と考えられます / 〜の可能性があります / 〜と思われます / 〜と言われています | 言い切るか、【推定】【要確認】のラベル | 語尾のぼかし。W09 |
| 〜が求められています | 〜が要ります / 〜してください | 受動の翻訳調 |
| 私は / あなたは（不要な主語） | 省く | 英語の主語をそのまま置いた形 |
| 判断が出た / 指摘が出た / 検出が出た | 〜と判断した / 〜と指摘された / 〜を検出した | 行為を名詞にして「出た」で受ける自分の癖（2026-09-16 の棚卸しで3件） |
| 見ていただければです | 見ていただけますか / ご確認ください | 仮定形で止めて「です」を付ける口語。Slackでも述語まで書く |
| 直近具体的にやることは | 直近やることは | 「直近」と「具体的に」が重なる |

## 翻訳調の構文（lint W17）

英語の構文を日本語の語順に置き換えた型。語ではなく文の組み立てなので、`lint-draft` が正規表現で拾う。出典は coji/natural-japanese の `translationese.md`。

| ❌ 避ける | ⭕️ 使う | 備考 |
| :--- | :--- | :--- |
| 〜することができる / 〜することが可能です | 〜できる / 〜できます | canの直訳。説明書調になる |
| 〜することによって | 〜すると / 〜して | by ~ingの直訳 |
| 〜という点で / 〜という観点から | 〜については / 〜で見ると | in terms ofの定訳 |
| 〜にとって重要 / 〜にとって不可欠 | 〜には〜が要る | 抽象的な重要性より具体的な必要性 |
| 大きな意味を持つ / 影響を持つ | 意味がある / 影響がある | haveの直訳。抽象名詞に「持つ」を付けない |
| であることは間違いない / に他ならない | 根拠を先に書いて言い切る | 論証なしの強調 |
| この結果は〜を示している / この事実が〜をもたらす | この結果から〜と分かる / 〜のため〜になる | 無生物主語＋他動詞。誰の判断かが消える |
| それは〜である。なぜなら〜だ | 〜のため〜である（1文に） | cleft構文の直訳。理由は前に置く |
| ——つまり〜——（ダッシュ挿入） | （〜）か、文を分ける | em-dashの直訳 |

## 文の組み立て（lint W18〜W20）

| 癖 | 目安 | 直し方 |
| :--- | :--- | :--- |
| 否定→肯定の対比の反復（W18） | 1つの下書きに2回以上（Slackは1回でも） | 本当の誤解の訂正だけ残し、他は肯定形に |
| 同じ文末の連続（W19） | 〜ます。〜ます。〜ます。が3文（Slackは4文） | 体言止め・条件文・名詞文を混ぜる。語尾だけ変えて逃げない |
| 一文が長い（W20） | 90字超、または読点4つ以上 | 主張ごとに文を切る。原因を先に、結果を後に |
| 原因の後置き | 「Aが起きます。Bのためです」 | 「BのためAが起きます」と1文に |
| 用語を先に投げる | 「`避難誘導モード`は〜する機能」 | 機能を説明してから名前を渡す。初出に一言の注釈 |

## 書き方の目安

1. **文は日本語、固有名詞は英語のまま**: `shadow_predictions`テーブルへ記録する
2. **カタカナ定着語はカタカナ**: キュー、フラグ、シャドー、バックフィル、ペイロード
3. **直訳漢語を疑う**: 結線・消化（チェック）・処遇・投下（deploy以外）
4. **比喩動詞**: 既定値は「既定する」、振分は「振り分ける／送る」。公開操作はON/OFF
5. **英語セクション見出しを避ける**: In/Out → 対象/対象外
6. **可観測性と監視を混ぜない**: ログ/トレース/メトリクスの能力は可観測性。アラームは監視
7. **数字と英略語を直結しない**: 助数詞を日本語で付ける（9IP → IP 9件、3PR → PR 3本）
8. **結論を最初の一文に。前置き・予告・数の宣言を書かない**: 「本稿では」「理由は3つ」「見ていきましょう」は削る
9. **確信度はラベルで書き分ける**: 断定 / 【推定】 / 【要確認】。語尾（〜と思われます）でぼかさない
10. **直すときは語の置換でなく文を書き直す**: 常套句を別の語に差し替えると同じ問題が別の語形で残る。補足・注記で逃げず、本文を元と同じ長さか短く

Issue・PR・ops文面を書くときは、投稿前にこの表を一度当たる。機械で拾えるものは `~/.claude/skills/factcheck/bin/lint-draft` が読む（「避ける」節の❌列と W17〜W20）。
